# 作業指示書

## 指示内容1　作業フォルダに関する情報

- チャットに以下のファイルを添付する
  - `login.html`、`product_list.html`、`order_detail.html`、`style.css`、`logo.svg`、`テーブル定義書（myappdb）.sql`
- 生成したプログラムは「`myapp_Python.zip`」としてまとめること
  - zipの格納場所と展開先は同じフォルダ「`C:\fellowsapp`」とする
  - 展開後は以下の状態になる
    - `C:\fellowsapp\myapp_Python.zip`
    - `C:\fellowsapp\manage.py`
    - `C:\fellowsapp\`（展開された資材：config、app、requirements.txt など）
    - `C:\fellowsapp\myappdb.sqlite3`（作成済みのDB）
  - zipの直下に `manage.py` を置くこと（上位フォルダを作らない）
  - `requirements.txt` を含めること
  - README・起動手順・`myappdb.sqlite3`・`venv` は含めない
- **zipの中のフォルダ構成は、以下に固定する**（これ以外のフォルダ・ファイルは追加しない）

```
myapp_Python.zip
├─ manage.py
├─ requirements.txt
├─ config/        （settings.py、urls.py、wsgi.py、asgi.py、__init__.py）
├─ app/           （models.py、views.py、urls.py、apps.py、__init__.py、templatetags/）
├─ static/        （style.css、logo.svg）
└─ templates/
   └─ app/        （login.html、product_list.html、order_detail.html）
```

  - テンプレートと静的ファイルは `app/` の中ではなく、zip直下の `templates/`、`static/` に置く
- **指示書に書かれていない項目**（フォルダ構成、ファイル名、設定など）は、勝手に決めずに質問すること
  - やむを得ず補った場合は、補った項目の一覧を回答の最後に出すこと
- 生成後、zipの中身をツリーで表示し、上記のフォルダ構成と一致することを確認して報告すること

## 指示内容2　生成物の条件定義

### (1) 以下の内容でPythonアプリを生成すること

- Python 3.12 以上、Django 6.1
- プロジェクト名：「config」、アプリ名：「app」
- DBMS：SQLite

### (2) DBはSQLiteのファイル(myappdb.sqlite3)を利用すること

- `manage.py` と同じフォルダの `myappdb.sqlite3` を使う
- DBの接続設定は `settings.py` の `DATABASES` に書く
- `myappdb.sqlite3` は作成済みのため、アプリ側でのDB・テーブルの作成やデータ投入は行わない
- テーブル定義は以下を参照
  - 添付の `テーブル定義書（myappdb）.sql`（テーブル構造の参照用。実行は不要）

> **補足**：DBファイルのパスは `settings.py` の `BASE_DIR` を基準に指定し、`C:\fellowsapp` を固定で書かないこと

### (3) セッション管理は署名付きCookieを利用すること

- `SESSION_ENGINE = "django.contrib.sessions.backends.signed_cookies"`
- DB(myappdb.sqlite3)にセッション用のテーブルを作成しない

### (4) 画面のURL

| URL | 画面 |
|---|---|
| `/login/` | ログイン画面（ログイン不要の画面はこの画面のみ） |
| `/logout/` | ログアウト（POST。実行後は「ログイン画面」へ遷移） |
| `/products/` | 商品一覧画面 |
| `/orders/?code=商品コード` | 注文情報詳細画面 |

- `/` は `/products/` へリダイレクトする（未ログイン時は `/login/` へ）

### (5) HTMLのテンプレート化と設定

- HTMLはDjangoテンプレートにする。CSS・`logo.svg` は `{% static %}`、リンクとformのactionは `{% url %}` で指定する
  - デザイン・クラス名・構造は変更しない
- 全てのform（ログイン、ログアウト）に `{% csrf_token %}` を追加する
- テンプレートは `templates/app/`、静的ファイルは `static/` に配置する（zip直下。`app/` の中には置かない）
- `settings.py` の `TEMPLATES` の `DIRS` に `BASE_DIR / 'templates'`、`STATICFILES_DIRS` に `[BASE_DIR / 'static']` を指定する
- `settings.py` に `LANGUAGE_CODE = 'ja'`、`TIME_ZONE = 'Asia/Tokyo'` を指定する

## 指示内容3　ログイン画面

### (1) 以下の内容で「ログイン画面」を生成すること

- 画面レイアウトは以下に準拠
  - `login.html`
  - `login.html` から参照されるファイルも参照すること

### (2) ログイン時の認証を組み込む

#### (2-1) ログイン認証用アイテム

- 「ユーザ名」
- 「パスワード」

#### (2-2) ログイン時の認証方法

- [ユーザー情報テーブル]の値との一致を認証
  - 「ユーザ名」：[eメール]と値が完全一致すること（大文字小文字を区別する）
  - 「パスワード」：SHA-256（ソルトなし）でハッシュ化されたパスワードとの検証関数を利用すること
    - 入力値をUTF-8でSHA-256ハッシュ化（16進小文字64桁）し、DBの値と `hmac.compare_digest` で比較する関数を自作する
    - （Django標準の `check_password` は使用しない）

#### (2-3) ログイン認証に成功

- 「商品一覧画面」に遷移
- セッションにユーザーidを保存する

#### (2-4) ログイン認証に失敗

- 再度ログイン画面を表示
- エラーメッセージは認証失敗時のみ表示する
  - （`login.html` のサンプルはエラーメッセージが常に表示される状態のため、初回表示時などは表示しないこと）
- 「ユーザ名」と「パスワード」のどちらが誤りかは区別せず、同一のメッセージを表示する

> **補足**：ログイン認証失敗時には以下のメッセージをメッセージエリア（HTML上の `p.error-message`）に表示
> 「ユーザ名またはパスワードが正しくありません。」

#### (2-5) ログイン済みの状態で「ログイン画面」を開いた場合

- 「商品一覧画面」へリダイレクト

### (3) 動作確認用アカウント

DB登録済み。`myappdb.sqlite3` のパスワード情報は変更しない。

- ユーザ名：`user@example.com`
- パスワード：`1234`

## 指示内容4　商品一覧画面

### (1) 「商品一覧画面」の生成

- 画面レイアウトは以下に準拠
  - `product_list.html`
  - `product_list.html` から参照されるファイルも参照すること

### (2) ログイン認証を経由せずに「商品一覧画面」へ遷移した場合

- 「ログイン画面」へリダイレクト

### (3) ログアウトボタン

- 「商品一覧画面」からログアウトし「ログイン画面」へ遷移する

### (4) 「商品一覧情報」の生成

- [商品テーブル]と[注文テーブル]を取り込む

#### (4-1) [商品テーブル]は全件取り込む

- [廃番商品テーブル]は対象外とする（取り込まない）

> **補足**：[注文テーブル]に存在しても[商品テーブル]に存在しない商品コード（廃番商品など）の注文は、一覧に表示されない

#### (4-2) [商品テーブル]は[注文テーブル]とLEFT JOINする

- 結合キー：「商品コード」

#### (4-3) 「商品コード」ごとにGROUP BYし、注文件数を `COUNT(DISTINCT 注文番号)` で求める

- LEFT JOINにより、商品ごとに注文の行数分だけ行が重複するため、GROUP BYで商品ごとの1行にまとめる
- 注文のない商品は注文件数が0になる

### (5) 「商品一覧画面」への情報セット

#### (5-1) (4)で生成した「商品一覧情報」から画面に表示する項目をすべてセットする

- 「商品コード」の昇順で表示
- 「商品一覧画面」の「注文状況」に[注文テーブル]から取り込んだ情報が存在する商品には、「注文番号」の種類数(4-3の注文件数)を「件数」として表示する
- 「商品名」はCSSで25文字分の幅に収め、超える場合は省略記号(…)を表示する（DBの値は切り詰めずに出力し、`title` 属性に商品名全体を設定する）
- 各カラムの表示形式はHTMLに準拠する

> **補足**：「件数」は「注文番号」の種類数であり、「注文情報詳細画面」の表示行数（注文枝番単位）と一致しない場合がある

#### (5-2) 「注文状況」のカラムには「注文情報詳細画面」へのリンクを張る

- 注文情報が存在しない商品の「注文状況」は「注文なし」と表示し（HTMLに準拠）、リンクは張らない

## 指示内容5　注文情報詳細画面

### (1) 「注文情報詳細画面」の生成

- 画面レイアウトは以下に準拠
  - `order_detail.html`
  - `order_detail.html` から参照されるファイルも参照すること

#### (1-1) ログイン認証を経由せずに「注文情報詳細画面」へ遷移した場合

- 「ログイン画面」へリダイレクト

#### (1-2) 「商品コード」(code)が未指定、または[商品テーブル]に存在しない場合

- 「商品一覧画面」へリダイレクト
- 注文のない商品のURLを直接開いた場合は、注文の一覧を空の状態で表示する

#### (1-3) 「注文情報詳細画面」では各商品ごとの「注文」情報を一覧表示する

- [注文テーブル]から、選択された商品の「商品コード」に一致する注文を取得し、画面に表示する項目をすべてセットする
- 「注文日」、「注文番号」の降順で表示する（同じ場合は「注文枝番」の昇順）

#### (1-4) 「クーポン割引料」の表示形式

- プラスの金額：「+」の符号を付けて表示する（例：+150）
- マイナスの金額：「-」の符号を付け、赤字で表示する（例：-500）
- 0：符号を付けず「0」と表示する
- NULLの場合：空欄とする
- カンマ区切りで表示する（HTMLに準拠）

#### (1-5) ログアウトボタン

- 「注文情報詳細画面」からログアウトし「ログイン画面」へ遷移する

#### (1-6) 「← 商品一覧に戻る」リンク

- 「商品一覧画面」へ遷移する
