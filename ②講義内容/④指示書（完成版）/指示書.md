## 指示内容１ 作業フォルダに関する情報

- 添付時にファイル名に「_1」などが付いても同じファイルとして扱い、出力するファイル名は元の名前(style.css、logo.svg など)を使うこと
- 生成したプログラムはzipファイルとしてまとめること
- zip の直下に manage.py、config、app、static、templates、requirements.txt を置く(venv と myappdb.sqlite3 は含めない)

> **補足**

## 指示内容２ 生成物の条件定義

### (1)以下の内容でPythonのWebアプリを生成すること
- Python 3.12 以上、Django 6.1
  - Django プロジェクト名："config"、アプリ名："app"
  - 開発環境：VSCode(venv を作成して利用)
  - `DBMS:SQLite(Python 組み込みの sqlite3 を使う。追加のライブラリは入れない)`

### (2)プロジェクトの構成
- settings.py はローカル開発用の通常設定だけを書く。STATIC_ROOT、FORCE_SCRIPT_NAME、本番用の切り替えは書かない
- INSTALLED_APPS は django.contrib.staticfiles、app の2つだけにする(sessions・auth・admin・contenttypes・messages は入れない)
- セッションは署名付き Cookie に保存する(SESSION_ENGINE = 'django.contrib.sessions.backends.signed_cookies')。セッション用のテーブルは作らないので、python manage.py migrate は不要
- MIDDLEWARE は SecurityMiddleware、SessionMiddleware、CommonMiddleware、CsrfViewMiddleware、XFrameOptionsMiddleware とする
- `LANGUAGE_CODE='ja'、TIME_ZONE='Asia/Tokyo'、DEBUG=True、ALLOWED_HOSTS=['127.0.0.1', 'localhost']`
- テンプレートは templates/app/ 配下に置き、{% url %} と {% static %} を使う
- style.css と logo.svg は、プロジェクト直下の static/ にコピーする(settings.py に STATICFILES_DIRS = [BASE_DIR / 'static'] を書く)
- フォーム(ログイン・ログアウト)には {% csrf_token %} を入れる
- パスの比較が必要な場合は request.path_info を使う
- requirements.txt を作成する(gunicorn は含めない)。pip を実行できない環境では次の1行を書く
  - `Django>=6.1,<6.2`

> **補足**  
> auth 系を入れないため、Django 標準のログイン機能は使わずセッションで判定する。  
> 署名付き Cookie のセッションなので、SECRET_KEY が変わるとログイン状態は無効になる(再ログインすればよい)  

### (3)画面の URL
- GET /login … ログイン画面を表示、POST /login … ログイン認証
- GET / … /login へリダイレクト
- GET /products … 商品一覧画面
- GET /orders?code=商品コード … 注文情報詳細画面
- POST /logout … セッションを破棄し /login へリダイレクト
- ログイン中かどうかはセッションのキー "loginUser" の有無で判定する

### (4)DB は SQLite のファイル(myappdb.sqlite3)を使う。SECRET_KEY は環境変数があればそれを使う
- DATABASES は次のとおりにする
  - `ENGINE`：`django.db.backends.sqlite3`
  - `NAME`：`BASE_DIR / 'myappdb.sqlite3'`(manage.py と同じフォルダのファイル)
- SECRET_KEY は `os.environ.get('DJANGO_SECRET_KEY', 'local-dev-key-change-me-0123456789')` とする(環境変数が無ければ開発用の値を使う)
- 環境変数の設定は、ローカルでは不要

> **補足**  
> myappdb.sqlite3 は、環境構築で C:\fellowsapp(manage.py と同じフォルダ)にあらかじめ配置される。生成した zip を C:\fellowsapp に展開して上書きしても、このファイルは消えない(zip に含めない)。プログラムでは作らない。  
> ファイルが無いまま起動すると、Django が空の DB を新しく作ってしまい、「no such table」のエラーになる  

### (5)テーブル定義と初期データは以下の SQL ファイルを参照
- テーブル定義書（myappdb）.sql
- DDL(CREATE TABLE)と初期データ(INSERT)が書かれている。テーブル名・列名・型・主キーはこのファイルのとおりにする
- プログラムからはテーブルの作成・データ投入・削除(DDL/DML)を実行しない。データの読み取り(SELECT)だけを行う
- [廃番商品]テーブルは本アプリでは使わない
- 業務テーブルは既存。モデルは managed = False とし、db_table と db_column に日本語のテーブル名・列名を指定する
- [注文テーブル]の主キーは models.CompositePrimaryKey("注文日", "注文番号", "注文枝番") で定義する
- 集計が必要な商品一覧は django.db.connection の cursor で SQL を実行してよい(値はプレースホルダ %s で渡す)

> **補足**  
> makemigrations と migrate は実行しない(テーブルはあらかじめ用意された myappdb.sqlite3 にある)  
> このSQLは各テーブルを DROP TABLE で削除して作り直す。SQLite 用に書かれており、日付は 'YYYY-MM-DD' の文字列で入っている。  
> myappdb.sqlite3 は、このSQLを実行して作成済みのもの(同じ内容)  


## 指示内容3 ログイン画面

### (1)以下の内容で「ログイン画面」を生成すること
- 画面レイアウトは以下に準拠
  - `login.html`
  - login.htmlから参照されるファイルも参照すること

### (2)ログイン時の認証を組み込む

### (2-1)ログイン認証用アイテム
- ”ユーザ名”
  - ”パスワード”

### (2-2)ログイン時の認証方法
- [ユーザー情報]テーブルの値との一致を認証する
  - ”ユーザ名”：[ユーザー情報].eメール と値が一致すること
  - ”パスワード”：入力値を UTF-8 のバイト列にして SHA-256 でハッシュ化し、小文字16進数64桁の文字列にしたものが [ユーザー情報].パスワード と一致すること(ソルトなし)
- ハッシュ化には hashlib.sha256(password.encode('utf-8')).hexdigest() を使う
- Django の make_password / check_password は使わない

> **補足**  
> 確認用のユーザー(user@example.com)で、そのままログインできる。  
> 確認用ユーザーはテーブル定義書(sql)の初期データで登録済み。  
> ユーザ名:user@example.com  
> パスワード:1234(DB には SHA-256 のハッシュ値が入っている)  

### (2-3)ログイン認証に成功：
- セッションの "loginUser" に eメール を保存し、「商品一覧画面」(/products)へリダイレクト

### (2-4)ログイン認証に失敗：
- 再度ログイン画面を表示

> **補足**  
> ログイン認証失敗時には以下のメッセージをメッセージエリアに表示(html に準拠)  
> 「ユーザ名またはパスワードが正しくありません。」

### (1)「商品一覧画面」の生成

### (3)ログアウトボタン
- html に合わせ POST /logout で「商品一覧画面」からログアウトし「ログイン画面」へ遷移する

### (4)「商品一覧情報」の生成
- [商品テーブル]と[注文テーブル]を取り込む

### (4-1)[商品テーブル]は全件取り込む

### (4-2)[商品テーブル]は[注文テーブル]とLEFT JOINする(結合キー：”商品コード”）

### (5)「商品一覧画面」への情報セット

### (5-1)(4)で生成した「商品一覧情報」から画面に表示する項目をすべてセットする
- ”商品コード”の昇順で表示
- ”注文状況”には、[注文テーブル]に情報が存在する商品について ”注文日”と”注文番号”の組の種類数を”件数”として「注文(n 件)」の形式で表示する
- 件数は次の式で数える(注文が無い商品は 0 件になる)
  - `COUNT(DISTINCT o.注文日 || '|' || o.注文番号)`
- 件数が 0 件の商品は「注文なし」と表示する
- 各カラムの表示形式は html に準拠する(カンマ区切りなどの整形は view かカスタムテンプレートフィルタで行う)

> **補足**  
> 主キーに注文日が含まれ、別の日に同じ注文番号があり得るため、注文日と注文番号の組で数える。  
> django.contrib.humanize は INSTALLED_APPS に入れない  
> SQLite の COUNT(DISTINCT …) には、列を 2 つ並べて書けない。そのため 2 列を文字列として連結して数える  
> LEFT JOIN で注文が無い商品は連結した値が NULL になり、COUNT では数えられないので 0 件になる  

### (5-2)”注文状況”のカラムには「注文情報詳細画面」(/orders?code=商品コード)へのリンクを張る
- ”注文”情報が存在しない”商品”の”注文状況”は「注文なし」と表示しリンクは張らない(html に準拠)
- ”関連商品コード”が無い場合は「―」と表示する(html に準拠)

## 指示内容６ 動作確認

### (1)生成後に以下の手順で起動できるようにすること
- `pip install -r requirements.txt`
- myappdb.sqlite3 は、zip を展開するフォルダ(manage.py と同じフォルダ)にあらかじめ置いてある
- python manage.py runserver で http://127.0.0.1:8000/login を開く
- 動作確認後に pip freeze で requirements.txt をバージョン付きに作り直す

> **補足**  
> requirements.txt の作り直し:  
> `cmd … python -m pip freeze > requirements.txt`  
> `PowerShell … python -m pip freeze | Out-File -Encoding ascii requirements.txt`  
> (PowerShell の > は UTF-16 になるため使わない)
